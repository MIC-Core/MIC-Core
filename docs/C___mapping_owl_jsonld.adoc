[appendix]
== Mapping of MIC Core to OWL Ontology and JSON-LD

This appendix is an optional part of the MIC Core specification.
It provides a formal representation of the MIC Core standard attributes as an OWL ontology, a SHACL shape model for validation, and a JSON-LD context for serialisation.
These artefacts allow MIC Core metadata to be expressed and exchanged using standard Semantic Web technologies.

=== Introduction

==== Semantic Web Technologies

The Semantic Web stack provides a family of interoperable standards that enable the unambiguous description and exchange of structured data across systems and organisations.
The key standards used in this appendix are:

* **RDF** (Resource Description Framework) – a graph-based data model in which facts are expressed as subject–predicate–object triples.
* **OWL** (Web Ontology Language) – an RDF vocabulary for defining classes, properties, and logical constraints, enabling formal machine-readable knowledge representation.
* **SHACL** (Shapes Constraint Language) – an RDF vocabulary for expressing structural and value constraints on RDF graphs, used here to validate MIC Core metadata.
* **JSON-LD** (JSON for Linked Data) – a JSON-based serialisation format for RDF that uses a context document to map compact JSON terms to full ontology IRIs.

==== Design Decisions

The MIC Core ontology assigns a single OWL class `mic:SimulationModel` to represent a simulation model.
All MIC Core attributes are modelled as OWL properties whose domain is `mic:SimulationModel`.
Attributes with textual or date values use `owl:DatatypeProperty`, while the Verification & Validation Report attribute, which carries an IRI reference, uses `owl:ObjectProperty` with range `mic:Report`.

The ontology namespace is `https://mic-core.org/ontology/mic-core#` with preferred prefix `mic`.

The SRMD keyword mapping from <<Appendix A>> is preserved in the ontology as `skos:mappingRelation` annotations on each property.

=== SHACL Shape Model

The MIC Core SHACL shape model is provided as a Turtle file (`ontology/mic-core-shacl.ttl`).
It defines a `sh:NodeShape` targeting `mic:SimulationModel` instances and validates the cardinality and datatype of every MIC Core property.

The SHACL constraint severity follows the MIC Core obligation levels:

* `sh:Violation` – constraint on a Mandatory attribute.  Conforming data MUST satisfy these constraints.
* `sh:Warning` – constraint on a Recommended attribute.  Conforming data SHOULD satisfy these constraints.
* `sh:Info` – constraint on an Optional attribute.  No cardinality is enforced; the shape serves as documentation only.

=== JSON-LD Mapping

JSON-LD uses a context document to map compact JSON terms to their full IRI counterparts, enabling interoperability with the RDF data model.
The MIC Core JSON-LD context (`ontology/mic-core-context.jsonld`) provides the following mapping:

* The JSON key `"@type": "SimulationModel"` expands to `mic:SimulationModel`.
* All attribute keys expand to the corresponding `mic:` property IRI.
* Single-value attributes are represented as plain JSON values.
* Multi-value attributes use `"@container": "@set"`, so they are always represented as a JSON array even when only one value is present.
* The `releaseDate` attribute is typed as `xsd:date`.
* The `verificationValidationReport` attribute is typed as `"@type": "@id"`, meaning each value is an IRI.  Report resources may carry a `"label"` key (mapping to `rdfs:label`) for a human-readable name.
